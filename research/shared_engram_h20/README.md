# Shared Engram H20 research adaptation

Experimental, default-off integration on SGLang H20 base commit `6e6d5d9e13915adb01db0856b15d6908eaaa2c48`. The Python reader files here match the files loaded in the measured H20 run. This is research code, not a supported production deployment or a self-contained package.

## Dependencies and configuration

The reader uses a separately built legacy DOCA 3.1 / NIXL GPUNETIO native library and a checkpoint-backed owner service. [The public legacy NIXL reproducer](https://github.com/foraxe/nixl/tree/b5322e46f6e686ff16bdb3afb8a1a940a64e1163/research/vllm_engram_repro) includes native sources, build instructions and example owner tools. It is a separate research snapshot; its rebuild was validated independently and has not been established as binary-identical to the serving measurement here. NIXL [#2544](https://github.com/ai-dynamo/nixl/pull/2544) is a distinct API proposal, not this library implementation. The owner needs the same checkpoint identity as the model and compatible row264 layout. Owner metadata, addresses, ports and model weights must be provided by the operator; do not publish them. Allocation of the complete owner table requires substantial pinned host memory.

Put this directory and the SGLang `python` directory on `PYTHONPATH`. On prefill only, enable `SGLANG_EXPERIMENTAL_REMOTE_ENGRAM=1` and `SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1`, with `SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT=private`. The measured reader used `ENGRAM_SHARED_PREFETCH=1`, `ENGRAM_SHARED_READ_PLAN=1`, `ENGRAM_SHARED_READ_LANES=16`, `ENGRAM_SHARED_MAX_QUERIES=393216`, `ENGRAM_SHARED_READ_GRAPH_SIZES=393216`, and `ENGRAM_SHARED_DEFER_LAYER14=1`. Set `ENGRAM_SHARED_READY`, `ENGRAM_SHARED_MODEL`, `ENGRAM_SHARED_LIBRARY`, `ENGRAM_SHARED_READER_PORT_BASE` and network configuration for the environment. Set `ENGRAM_SHARED_READER_DEVICES` to a comma-separated device per local GPU; the measured eight readers used two devices in a 4+4 assignment. Decode remained native. These variables are a configuration inventory, not a complete turnkey deployment recipe; no serving launch is provided without environment-specific owner and library setup.

## Measured result and scope

On 1P1D H20, P TP8/CP8, 16,384 input and 64 output tokens, C8: native and shared TTFT p50 were 1554.647 ms and 1553.763 ms, respectively (median of three per-round medians; 8 warmup and 32 measured requests per round). The same D was used for both arms, but P and D used different source revisions. All 96 paired request/input and final-text hashes matched, with zero measured cache hits, retractions or client errors. P was restarted, and arms ran in fixed order; these are three rounds, not independent deployment restarts. Per-round p99 from 32 requests is exploratory. The ~0.88 ms p50 difference is not evidence of a shared-path speedup.

The shared arm uses a separate owner table in host memory, reducing per-instance table replicas while retaining one owner. The result does not establish 3P1D, other concurrency levels, current DOCA SDK compatibility, or production readiness. The use of graph capture is restricted: unexpected direct remote lookup during QP-prefetch capture fails closed. Resource lifetime, cancellation and connection recovery require further work. The measurement predates this branch commit; the three patched SGLang files and eight reader Python files were checked against the measurement's SHA-256 hashes. The binaries and service environment are external to the branch.

## Public runtime integration check

A subsequent H20 check used the separately rebuilt NIXL core, GPUNETIO plugin and ABI-3 shim from the linked legacy research source. On SGLang's public H20 integration, one reader checked four real checkpoint rows in each of layers 1 and 14; the 16-QP prefetch path then checked 4096 selections per layer, including duplicate restoration, and completed four graph replays. Both readers closed successfully. Process mappings verified the rebuilt core, plugin and shim were actually loaded. The single-reader tests used the existing remote checkpoint owner; they do not independently qualify owner startup or cleanup.

With the same rebuilt libraries loaded by all eight P ranks, a two-node 1P1D 16K-input/8-output greedy request completed with zero cached tokens and matched the output text hash of the earlier runtime on the same request. P was restarted; D and the existing owner remained running. This is one functional canary, not a performance comparison, broad model accuracy test, or a validation of owner lifecycle. The earlier 1.554 s performance number remains attributed to the prior runtime and the integration source at commit `5058e1fe5`.
